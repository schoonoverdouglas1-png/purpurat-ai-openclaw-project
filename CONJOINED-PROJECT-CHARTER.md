## Borrow order (the order we build in)
Gateway / control plane → session & identity isolation → approvals
(read / write / execute tiers) → channel pairing → health & audit →
scheduled automation → skills.

## Patterns adopted from the reverse-engineering (Nov 14, 2026, credited)
1. Approvals registered on the system side BEFORE the ask is shown —
   ~30-min expiry, garbled verdict forced to deny, "allow always"
   becomes a scoped grant with frozen expiry; background jobs register
   and expire quietly.
2. One gateway speaking request / response / event frames; handshake
   grants scoped read-vs-write roles plus a reusable device token.
3. Pairing as a bounded ceremony — 8-character code, no look-alike
   letters, 1-hour validity, max 3 pending, dismiss ≠ block.
Runner-up: cron execution vs delivery tracked separately; broken job
definitions quarantined; scheduled runs get a smaller permission set.

## Crew rules (non-negotiable, from the Captain)
The Guard stands (no automatic destructive action, ever). Deny first,
allow last. Oldest first; backward compatibility before forward.
Translation outside the app, never inside; used from outside when
needed. Plain text first — text gets through every channel. Credit
kept on everything borrowed. Morality is the enforcement.
